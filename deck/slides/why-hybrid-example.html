A Hybrid

Split, In Practice

Route by sensitivity, not by tool

Stays local

  • Proprietary source code and internal architecture
  • Customer data, PII, or anything under NDA
  • Secrets, credentials, and internal API contracts
  • Regulated data (health, financial, government)

Fine for a hosted model

  • Public docs, open-source code, and boilerplate
  • General "how do I..." and library/API questions
  • Public-facing marketing or support copy
  • Anything already published or open-source licensed

Ollama itself doesn't decide this for you, it dispatches by which model tag you pick, not by reading what's in the prompt. The gate has to be a team norm, or a proxy layer we build in front of it, open-source options like LiteLLM or Occludra Gateway exist, out of scope for today.

Concrete example for orgs with mixed sensitivity: keep the local model as the default for anything touching the codebase or customer data, and let hosted/cloud models handle general questions and public content where the bigger, non-local models pay off. If asked "can Ollama enforce this": no — it routes by which model tag you pick (including its own :cloud tags), not by reading the prompt. LiteLLM (open-source proxy, supports Ollama plus ~100 cloud providers, tag-based routing rules) and Occludra Gateway (open-source PII/secret redaction and prompt-injection blocking) are the tools I'd point to if someone wants to go build this — worth its own session, not this one.
