What "thinking mode" does

Qwen's thinking-switchable models generate a chain-of-thought block before the actual answer, useful for hard reasoning, wasted latency for a quick autocomplete or chat reply.

Why it's easy to miss

There's no per-model toggle in the Ollama VS Code connector's UI today, it's on unless you explicitly turn it off elsewhere.

This matches what I found in Ollama's own tracker: thinking is a per-request or per-Modelfile setting, not something the VS Code extension currently exposes as a toggle. The sample is illustrative — point at the pink block and note that in an editor you often do not even see it, you just wait.
